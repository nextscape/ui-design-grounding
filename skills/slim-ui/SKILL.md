# slim-ui

## 準備（MANDATORY PREPARATION）

ui-design-grounding スキルを呼び出し、以下のリファレンスを読み込む:

- `ui-design-grounding/reference/cognitive.md`
- `ui-design-grounding/reference/information-arch.md`
- `ui-design-grounding/reference/usability.md`
- `ui-design-grounding/reference/anti-patterns.md`

## 手順

### 1. 要素の棚卸し

対象UI上のすべての要素を列挙し、以下を判断する:

| 要素 | ユーザーの目標達成に必要か | 代替手段はあるか | 削除可能か |
|------|------------------------|----------------|-----------|
| ... | はい/いいえ | ... | ... |

### 2. 削減の判断基準

以下の観点で不要な要素を特定する:

**情報の重複**:
- 見出しが本文と同じ内容を繰り返していないか
- 同じ情報が複数箇所に表示されていないか
- ラベルと値が冗長でないか

**装飾の過剰**:
- 機能的でないアイコン
- 装飾的なボーダー・区切り線
- 意味のないカード包み
- 過剰なシャドウ・グラデーション

**機能の過剰**:
- 主要タスクに不要なボタン・リンク
- めったに使われない設定・オプション
- 段階的開示で十分な補助情報

**認知負荷**:
- Cowanの限界（4項目）を超える同時表示
- ナビゲーション項目が5つを超える
- フォームフィールドが4つ/グループを超える

### 3. 削減の実施

**段階的開示への変換**:
- 補助情報をデフォルト非表示にする
- `<details>/<summary>` や折りたたみパネルに移動
- "詳細を表示" リンクで展開

**情報の統合**:
- 重複表示の統合
- 関連情報のグルーピング
- 冗長なラベルの削減

**要素の削除**:
- 機能的でないアイコンの除去
- 不要な区切り線・ボーダーの除去
- 過剰な装飾の除去
- 使われていない機能の非表示化

**レイアウトの簡素化**:
- カードのフラット化
- 階層の削減
- 余白による整理（区切り線ではなく余白で分離）

### 4. バランス検証

- **スリム ≠ 情報不足**: ユーザーが目標を達成するために必要な情報は残す
- **スリム ≠ 退屈**: 視覚階層と優先順位は維持する
- 削除した要素にアクセスする代替手段があるか確認
- ニールセンのH8（美的でミニマルな設計）を参照
