## このドキュメントの役割
**認知科学（知覚・記憶・注意・意思決定）の観点からUI/UXを判断・評価するための基準と原則**を提供する。

## 認知科学とUI/UXデザイン

認知科学は人間の情報処理プロセスを扱う。UI/UXは認知負荷の軽減・予測可能性の向上・記憶負荷の最小化・注意の適切な誘導を目的に配慮する。

## 認知負荷の考え方

### 認知負荷とは

**情報を理解・処理するために必要な心理的努力**。3つのタイプがある：

1. **内在的負荷**（Intrinsic）：タスク自体の複雑さ。減らせないが、チャンキングや段階的開示で負担を軽減できる
2. **外在的負荷**（Extraneous）：提示方法による不要な負荷（不適切なレイアウト、混乱を招く表現、一貫性のないパターン等）。**ゼロに近づけることがUI設計の最重要目標**
3. **関連的負荷**（Germane）：学習・理解に役立つ負荷（パターン認識、メンタルモデル形成）。活用してユーザーの学習を促進する

**UI設計の目標：** 外在的負荷を最小化し、関連的負荷を活用し、内在的負荷は提示方法で軽減する。

### ワーキングメモリの限界（Cowanの限界）

従来「7±2」とされた短期記憶容量は、Cowan（2001）により**4項目**が実際の限界とされる。

**UIの具体的閾値：**

| 要素 | 推奨上限 | 理由 |
|---|---|---|
| ナビゲーションメニュー | トップレベル 5項目以下 | 一覧性と選択速度の両立 |
| フォームセクション | 1グループあたり 4フィールド以下 | 視覚的チャンクとしての認識限界 |
| アクションボタン | プライマリ1 + セカンダリ1〜2 | 選択肢が増えると判断が遅延する |
| 料金プラン・比較表 | 3プラン以下 | 比較対象が増えると選択困難になる |
| タブ・ステップ | 5つ以下 | 全体像の把握が困難になる |

**判断基準：** 4を超える項目を同時提示する場合はグルーピングか段階的開示を検討する。「7±2」はチャンクサイズの上限であり、UIの選択肢としては4がより安全な基準。

### 認知負荷を減らす原則

- **情報の整理：** 関連情報をグループ化（近接の法則）、階層を明確化、同時提示は4項目以内
- **視覚的支援：** 重要情報を強調、パターン・構造を視覚的に示す、余白で情報を分離
- **段階的開示：** 初期表示を最小限にし、詳細は必要時に展開

## 認知負荷チェックリスト（8項目）

順に確認し、認知負荷の問題を体系的に検出する。

### 1. シングルフォーカス（単一の焦点）
- 各画面・セクションに明確な1つの目的があるか
- 「この画面で何をすべきか」を即座に理解できるか

### 2. チャンキング（情報の塊化）
- 関連情報が意味のある塊にまとまっているか
- 各チャンクは4項目以内か

### 3. グルーピング（視覚的なグループ化）
- 近接の法則に基づき関連要素が視覚的にまとまっているか
- 余白やボーダーによる区切りが適切か

### 4. ビジュアルヒエラルキー（視覚的な階層）
- 情報の重要度が視覚的に明確か
- 最重要情報が最も目立っているか

### 5. ワンシングアットアタイム（1つずつ）
- 複雑なタスクがステップに分割されているか
- 各ステップの判断が1つに絞られているか

### 6. ミニマルチョイス（最小限の選択肢）
- 選択肢は必要最小限か
- デフォルト値や推奨が適切に設定されているか

### 7. ワーキングメモリ（作業記憶への配慮）
- ユーザーが情報を記憶して持ち運ぶ必要がないか
- 必要な情報は操作時点で画面上に提示されているか

### 8. プログレッシブディスクロージャー（段階的開示）
- 詳細情報は必要に応じて展開可能か
- 初期表示は最小限で、段階的に詳細を開示しているか

## 認知負荷の違反パターン

UIレビューで検出すべきパターン。各々に定義・検出方法・重篤度基準を示す。

### 1. Wall of Options（選択肢の壁）

**定義：** 多すぎる選択肢を一度に提示し選択を困難にする。Hickの法則により、選択肢が増えるほど判断時間は対数的に増加する。

**検出方法：**
- 同一画面内のクリッカブル要素が10個超
- ドロップダウンの選択肢が20個超
- フィルタ条件が5個以上同時表示
- グルーピングされていない長いリスト

**重篤度：**
- 高：主要タスクが選択肢に埋もれて困難
- 中：選択肢が多いが、グルーピングやフィルタで対処可能
- 低：補助機能の選択肢が多い（主要タスクに影響なし）

### 2. Memory Bridge（メモリブリッジ）

**定義：** ある画面の情報を記憶したまま別画面で操作させ、ワーキングメモリの限界を超える。

**検出方法：**
- 入力フォームで参照すべき情報が別画面にある
- 確認画面に元の入力内容が表示されない
- 比較対象が別タブ・別ページに分かれている
- エラーメッセージが該当フィールドから離れている

**重篤度：**
- 高：記憶すべき情報が3項目以上、または画面遷移が2回以上
- 中：記憶1〜2項目で、画面遷移が1回
- 低：同一画面内だがスクロールで離れた位置

### 3. Hidden Navigation（隠れナビゲーション）

**定義：** 重要なナビゲーションパスがデフォルト非表示で見つけられない。

**検出方法：**
- 主要機能へのアクセスがハンバーガーメニュー内のみ
- 重要操作がコンテキストメニュー（右クリック）でのみ可能
- スワイプ・長押し等の隠れジェスチャーでのみ到達できる機能
- 「設定」内に埋もれた重要操作

**重篤度：**
- 高：主要タスクに必要なナビゲーションが隠れている
- 中：よく使う補助機能のナビゲーションが隠れている
- 低：まれに使う機能のみが隠れている

### 4. Jargon Barrier（専門用語バリア）

**定義：** 対象ユーザーに理解困難な専門用語が説明なく使われる。

**検出方法：**
- ボタンやラベルに専門用語
- エラーメッセージに技術用語（HTTPステータスコード等）
- ヘルプや説明文がさらに専門用語で書かれている
- 略語が説明なく使用

**重篤度：**
- 高：主要操作のラベルやフローに専門用語があり操作が困難
- 中：補助情報に専門用語があるが主要操作に影響なし
- 低：専門家向けインターフェースでの適切な専門用語使用

### 5. Visual Noise Floor（ビジュアルノイズフロア）

**定義：** 競合する視覚要素が多すぎ、重要情報がノイズに埋もれる。

**検出方法：**
- 5秒見ても最重要情報がすぐ見つからない
- 強調手段（太字・色・アイコン・下線等）が3種類以上同時使用
- 余白不足で要素間の区切りが曖昧
- アニメーションが2箇所以上同時に動く

**重篤度：**
- 高：主要CTAやコンテンツが視覚ノイズに埋もれている
- 中：情報は見つかるが探すのに時間がかかる
- 低：装飾要素が多いが主要コンテンツの視認性は確保

### 6. Inconsistent Pattern（不一致パターン）

**定義：** 操作・デザインパターンが画面・コンポーネント間で一貫しない。

**検出方法：**
- 同じ操作が異なるUIで表現される（例：削除がある画面ではボタン、別画面ではスワイプ）
- 同じアイコンが異なる意味で使われる
- 同じ用語が異なる機能を指す
- レイアウトパターン（リスト・カード・テーブル）の使い分けに規則がない

**重篤度：**
- 高：主要操作のパターンが不一致で学習を転用できない
- 中：補助操作のパターンに部分的な不一致
- 低：視覚スタイルの軽微な不統一

### 7. Multi-task Demand（マルチタスク要求）

**定義：** 同時に複数のタスク・判断を要求する。注意の分割はエラーを招く。

**検出方法：**
- 1つのフォームステップで異なるカテゴリの入力を同時要求
- 制限時間がある状態で複雑な入力を要求
- 通知やアラートが作業中に頻繁に割り込む
- 入力と参照を同時に行う必要がある（= Memory Bridge と複合）

**重篤度：**
- 高：時間制約下での複数タスク要求、またはエラー時のリカバリが困難
- 中：同時タスクだが一時停止・中断が可能
- 低：軽微なマルチタスク（例：入力中のバリデーション表示）

### 8. Context Switch（コンテキストスイッチ）

**定義：** タスク途中で異なる概念・操作体系への切り替えを強制し、メンタルコンテキストを断ち切る。

**検出方法：**
- フロー途中で全く異なるUI体系の画面に遷移
- タスク完了前に無関係な設定・入力を要求
- モーダルが別のモーダルを開く（モーダル on モーダル）
- 入力途中で別アプリ・別システムへの遷移を要求

**重篤度：**
- 高：主要タスクのフロー内で発生し、離脱につながる
- 中：発生するが元のタスクに戻りやすい
- 低：オプショナルな操作でのみ発生

## 予測可能性と一貫性

### 予測可能性とは

ユーザーが**次に何が起こるかを予測できること**。高める要素：一貫性（同じ操作は常に同じ結果）、視覚的手がかり（操作可能な要素が明確）、フィードバック（操作結果が即座に分かる）、慣習の尊重（一般的なUIパターンに従う）。

### 一貫性のレベル

- **視覚的：** 同じ機能は同じ見た目、同じ意味は同じ表現、色・アイコンの意味が統一
- **操作的：** 同じ操作は同じ結果、手順が論理的、エラー時の挙動が一貫
- **言語的：** 用語が統一、メッセージのトーンが一貫

**判断に迷うケース（一貫性 vs 文脈最適化）：** 基本パターンは一貫させ、明確な理由がある場合のみ例外を許容（Inconsistent Pattern の違反に該当しないか確認）。

## 記憶負荷の軽減

### 記憶の種類とUI設計

- **ワーキングメモリ：** 容量 **4項目程度**（Cowanの限界）、保持数秒〜数十秒。→ 同時提示は4項目以内に制限
- **長期記憶：** 容量ほぼ無制限、保持長期間。→ ユーザーが覚えなくて済むよう情報を提示する

### 記憶負荷を減らす原則

- **認識 vs 想起：** 「思い出させる」より「認識させる」（例：テキスト入力よりドロップダウン）。Memory Bridge を避ける
- **情報の可視化：** 重要情報は常に表示、隠れた情報は最小限、必要情報は操作時に提示。Hidden Navigation を避ける
- **文脈の提供：** 現在の状態を明確に示し、操作結果を予測可能にし、エラー時は原因と解決方法を提示

## 注意の向け方（視覚階層、情報の優先順位）

### 注意の特性

人間の注意は**限られたリソース**。注意を引く要素：コントラスト（色・サイズ・明度）、動き、位置（上部・中央）、新奇性。

### 視覚階層の設計

優先順位を明確化する：(1) 最重要＝最も目立つ（大きい・高コントラスト・上部）(2) 重要＝中程度の強調 (3) 補助的＝控えめな表現。

**判断に迷うケース（複数の重要要素）：** 主要タスクに焦点を当て段階的に提示する。Visual Noise Floor の違反に注意。

### 情報の優先順位付け

**判断軸：** (1) ユーザーの主要目標 (2) 現コンテキストで必要な情報 (3) 次に必要な操作。

**実践原則：**
- 主要アクションを最も目立つ位置に配置、補助情報は折りたたむか控えめに表示
- エラー・警告は適切な優先度で表示（過度な強調は注意散漫を招く）
- アクションボタンはプライマリ1つ + セカンダリ1〜2つに制限

## 判断に迷いやすいポイント

### 情報量の調整（完全性 vs 認知負荷）
主要タスクに必要な情報を優先表示し、補助情報は展開可能に、詳細は段階的に開示する。同時提示する選択肢は4項目を目安に（Cowanの限界）、超える場合はグルーピング・カテゴリ分けで対処する。

### 一貫性と最適化のバランス
基本パターンは一貫させ、明確な理由（UX向上、文脈に応じた最適化）がある場合のみ例外を許容する。例：通常のフォームは一貫したパターン、特殊な入力（日付範囲選択等）は理由を明確にした上で専用UIも可。

### 視覚的強調の程度
最重要要素は明確に強調し、複数あれば優先順位を明確にする。過度な強調は注意散漫を招く。例：主要CTAは明確に強調、補助リンクは控えめに、エラーは適切な強調（過度ではない）。

## よくある失敗パターン

典型例と改善（詳細は上記「認知負荷の違反パターン」）。

- **Wall of Options** — 例：選択肢を詰め込み過ぎる。改善：段階的開示と優先順位整理、4項目以内のチャンクに分割
- **Memory Bridge** — 例：入力に必要な情報が別画面にある。改善：必要情報を操作画面に提示、比較は同一画面で
- **Visual Noise Floor** — 例：主要ボタンと補助リンクが同強度。改善：強調レベルを分け、Primaryを絞る
- **Inconsistent Pattern** — 例：同じ操作で異なる結果・表現が混在。改善：基本パターンを統一し例外は理由を明示
- **Jargon Barrier** — 例：エラーに「404」「500」のみ表示。改善：ユーザーの言葉で状況と解決方法を説明

## このreferenceの使い方

以下のコマンドスキルから参照される:
- `score-ui` — UI品質スコアリングの認知負荷評価時に参照

- `init-design` — デザインガイドライン策定時の認知科学的原則として参照
