## このドキュメントの役割
このドキュメントは、UI/UXデザインにおける
**認知科学の観点から判断・評価するための基準と原則**を提供する。

人間の認知プロセス（知覚、記憶、注意、意思決定）を理解し、
UI設計の判断に活用する。

## 認知科学とUI/UXデザイン

認知科学とは、人間の情報処理プロセスを研究する学問である。
UI/UXデザインは、この認知プロセスに配慮することで、
ユーザーの負荷を減らし、理解と操作を容易にする。

以下を目的とする：

- 認知負荷の軽減
- 予測可能性の向上
- 記憶負荷の最小化
- 注意の適切な誘導

## 認知負荷の考え方

### 認知負荷とは

認知負荷とは、**情報を理解・処理するために必要な心理的な努力**である。

**3つのタイプ：**

1. **内在的認知負荷**（Intrinsic Load）
   - タスクそのものの複雑さ
   - 例：複雑な計算、多くの選択肢からの選択
   - 減らすことはできないが、チャンキングや段階的開示で負担を軽減できる

2. **外在的認知負荷**（Extraneous Load）
   - 情報の提示方法による不要な負荷
   - 例：不適切なレイアウト、混乱を招く表現、一貫性のないパターン
   - **これをゼロに近づけることがUI設計の最重要目標**

3. **関連的認知負荷**（Germane Load）
   - 学習と理解に役立つ負荷
   - 例：パターンの認識、概念の構築、メンタルモデルの形成
   - 適切に活用することで、ユーザーの学習を促進できる

**UI設計の目標：**
- 外在的認知負荷を最小化する
- 関連的認知負荷を適切に活用する
- 内在的認知負荷は減らせないが、提示方法で負担を軽減する

### ワーキングメモリの限界（Cowanの限界）

従来「7±2」として知られていた短期記憶の容量は、
Cowan（2001）の研究により**4項目**が実際の限界であることが示されている。

**UIにおける具体的な閾値：**

| 要素 | 推奨上限 | 理由 |
|---|---|---|
| ナビゲーションメニュー | トップレベル 5項目以下 | 一覧性と選択速度の両立 |
| フォームセクション | 1グループあたり 4フィールド以下 | 視覚的チャンクとしての認識限界 |
| アクションボタン | プライマリ1 + セカンダリ1〜2 | 選択肢が増えると判断が遅延する |
| 料金プラン・比較表 | 3プラン以下 | 比較対象が増えると選択困難になる |
| タブ・ステップ | 5つ以下 | 全体像の把握が困難になる |

**判断基準：**
- 4を超える項目を同時に提示する場合は、グルーピングか段階的開示を検討する
- 「7±2」は記憶のチャンクサイズの上限であり、UIの選択肢としては4がより安全な基準

### 認知負荷を減らす原則

**情報の整理：**
- 関連する情報をグループ化する（近接の法則）
- 情報の階層を明確にする
- 一度に提示する情報量を4項目以内に制限する

**視覚的な支援：**
- 重要な情報を視覚的に強調する
- パターンや構造を視覚的に示す
- 余白を適切に使って情報を分離する

**段階的な開示：**
- 複雑な情報は段階的に提示する
- デフォルトで表示する情報を最小限にする
- 詳細は必要に応じて展開する

## 認知負荷チェックリスト（8項目）

UIの認知負荷を評価する際に使用する8項目のチェックリストである。
レビュー時にこのリストを順に確認することで、認知負荷の問題を体系的に検出できる。

### 1. シングルフォーカス（単一の焦点）
- 各画面・セクションに明確な1つの目的があるか
- ユーザーが「この画面で何をすべきか」を即座に理解できるか

### 2. チャンキング（情報の塊化）
- 関連する情報が意味のある塊にまとめられているか
- 各チャンクは4項目以内に収まっているか

### 3. グルーピング（視覚的なグループ化）
- 近接の法則に基づき、関連要素が視覚的にまとまっているか
- 余白やボーダーによる区切りが適切か

### 4. ビジュアルヒエラルキー（視覚的な階層）
- 情報の重要度が視覚的に明確か
- 最重要な情報が最も目立っているか

### 5. ワンシングアットアタイム（1つずつ）
- 複雑なタスクがステップに分割されているか
- 各ステップで要求される判断は1つに絞られているか

### 6. ミニマルチョイス（最小限の選択肢）
- 提示される選択肢は必要最小限か
- デフォルト値や推奨が適切に設定されているか

### 7. ワーキングメモリ（作業記憶への配慮）
- ユーザーが情報を記憶して持ち運ぶ必要がないか
- 必要な情報は操作時点で画面上に提示されているか

### 8. プログレッシブディスクロージャー（段階的開示）
- 詳細情報は必要に応じて展開可能か
- 初期表示は最小限で、段階的に詳細を開示しているか

## 認知負荷の違反パターン

UIレビュー時に検出すべき認知負荷の違反パターンを定義する。
各パターンには定義、検出方法、重篤度の判断基準を示す。

### 1. Wall of Options（選択肢の壁）

**定義：**
一度に多すぎる選択肢をユーザーに提示し、選択を困難にするパターン。
Hickの法則により、選択肢が増えるほど判断に要する時間は対数的に増加する。

**検出方法：**
- 同一画面内のクリッカブル要素が10個を超えている
- ドロップダウンの選択肢が20個を超えている
- フィルタ条件が5個以上同時に表示されている
- グルーピングされていないリストが長い

**重篤度の判断基準：**
- 高：主要タスクの達成が選択肢に埋もれて困難になっている
- 中：選択肢が多いが、グルーピングやフィルタで対処可能
- 低：補助的な機能の選択肢が多い（主要タスクには影響なし）

### 2. Memory Bridge（メモリブリッジ）

**定義：**
ある画面の情報を記憶したまま別の画面で操作することをユーザーに要求するパターン。
ワーキングメモリの限界を超える負荷をかける。

**検出方法：**
- 入力フォームで参照すべき情報が別画面にある
- 確認画面で元の入力内容が表示されていない
- 比較対象が別タブ・別ページに分かれている
- エラーメッセージが該当フィールドから離れた場所にある

**重篤度の判断基準：**
- 高：記憶すべき情報が3項目以上、または画面遷移が2回以上
- 中：記憶すべき情報が1〜2項目で、画面遷移が1回
- 低：同一画面内だが、スクロールで離れた位置にある

### 3. Hidden Navigation（隠れナビゲーション）

**定義：**
重要なナビゲーションパスがデフォルトで非表示になっており、
ユーザーが見つけられないパターン。

**検出方法：**
- 主要機能へのアクセスがハンバーガーメニュー内のみに存在する
- 重要な操作がコンテキストメニュー（右クリック）でのみ可能
- スワイプや長押しなどの隠れジェスチャーでのみ到達できる機能がある
- 「設定」内に埋もれた重要な操作がある

**重篤度の判断基準：**
- 高：ユーザーの主要タスクに必要なナビゲーションが隠れている
- 中：よく使う補助機能のナビゲーションが隠れている
- 低：まれに使う機能のみが隠れている

### 4. Jargon Barrier（専門用語バリア）

**定義：**
対象ユーザーにとって理解困難な専門用語や業界用語が、
説明なく使われているパターン。

**検出方法：**
- ボタンやラベルに専門用語が使われている
- エラーメッセージに技術的な用語（HTTPステータスコードなど）が含まれている
- ヘルプや説明文がさらに専門用語で書かれている
- 略語が説明なく使用されている

**重篤度の判断基準：**
- 高：主要操作のラベルやフローに専門用語があり、操作が困難
- 中：補助的な情報に専門用語があるが、主要操作には影響なし
- 低：専門家向けインターフェースでの適切な専門用語使用

### 5. Visual Noise Floor（ビジュアルノイズフロア）

**定義：**
画面上に競合する視覚要素が多すぎて、
重要な情報がノイズに埋もれるパターン。

**検出方法：**
- 画面を5秒見て、最も重要な情報がすぐに見つからない
- 太字、色、アイコン、下線などの強調手段が3種類以上同時に使われている
- 余白が不足し、要素間の区切りが曖昧
- アニメーションが2箇所以上同時に動いている

**重篤度の判断基準：**
- 高：主要なCTAやコンテンツが視覚ノイズに埋もれている
- 中：情報は見つかるが、探すのに時間がかかる
- 低：装飾的な要素が多いが、主要コンテンツの視認性は確保されている

### 6. Inconsistent Pattern（不一致パターン）

**定義：**
確立された操作パターンやデザインパターンが画面間・コンポーネント間で
一貫していないパターン。

**検出方法：**
- 同じ操作が異なるUIで表現されている（例：削除がある画面ではボタン、別の画面ではスワイプ）
- 同じアイコンが異なる意味で使われている
- 同じ用語が異なる機能を指している
- レイアウトパターン（リスト、カード、テーブル）の使い分けに規則がない

**重篤度の判断基準：**
- 高：主要操作のパターンが不一致で、ユーザーが学習を転用できない
- 中：補助的な操作のパターンに部分的な不一致がある
- 低：視覚的なスタイルの軽微な不統一

### 7. Multi-task Demand（マルチタスク要求）

**定義：**
ユーザーに同時に複数のタスクや判断を要求するパターン。
人間は本質的にマルチタスクが苦手であり、注意の分割はエラーを招く。

**検出方法：**
- 1つのフォームステップで異なるカテゴリの入力を同時に要求している
- タイマーや制限時間がある状態で複雑な入力を要求している
- 通知やアラートが作業中に頻繁に割り込む
- 入力と参照を同時に行う必要がある（= Memory Bridge と複合）

**重篤度の判断基準：**
- 高：時間制約下での複数タスク要求、またはエラー時のリカバリが困難
- 中：同時タスクだが、一時停止や中断が可能
- 低：軽微なマルチタスク（例：入力中のバリデーション表示）

### 8. Context Switch（コンテキストスイッチ）

**定義：**
ユーザーのメンタルコンテキスト（思考の文脈）を強制的に切り替えさせるパターン。
タスクの途中で異なる概念や操作体系への切り替えを要求する。

**検出方法：**
- フロー途中で全く異なるUI体系の画面に遷移する
- タスク完了前に無関係な設定や入力を要求する
- モーダルが別のモーダルを開く（モーダル on モーダル）
- 入力途中で別のアプリケーションやシステムへの遷移を要求する

**重篤度の判断基準：**
- 高：主要タスクのフロー内でコンテキストスイッチが発生し、離脱につながる
- 中：コンテキストスイッチは発生するが、元のタスクに戻りやすい
- 低：オプショナルな操作でのみコンテキストスイッチが発生する

## 予測可能性と一貫性

### 予測可能性とは

ユーザーが**次に何が起こるかを予測できること**である。

**予測可能性を高める要素：**

- **一貫性**：同じ操作は常に同じ結果を生む
- **視覚的手がかり**：操作可能な要素が視覚的に明確
- **フィードバック**：操作の結果が即座に分かる
- **慣習の尊重**：一般的なUIパターンに従う

### 一貫性のレベル

**視覚的一貫性：**
- 同じ機能は同じ見た目
- 同じ意味は同じ表現
- 色やアイコンの意味が統一されている

**操作的一貫性：**
- 同じ操作は同じ結果
- 操作の手順が論理的
- エラー時の挙動が一貫している

**言語的一貫性：**
- 用語が統一されている
- メッセージのトーンが一貫している

**判断に迷うケース：**
- 一貫性 vs 文脈に応じた最適化
- 判断：基本パターンは一貫させ、明確な理由がある場合のみ例外を許容
- Inconsistent Pattern（不一致パターン）の違反に該当しないか確認する

## 記憶負荷の軽減

### 記憶の種類とUI設計

**ワーキングメモリ（作業記憶）：**
- 容量：**4項目程度**（Cowanの限界）
- 保持時間：数秒〜数十秒
- UI設計への示唆：一度に提示する選択肢や情報を4項目以内に制限する

**長期記憶：**
- 容量：ほぼ無制限
- 保持時間：長期間
- UI設計への示唆：ユーザーが覚えなくて済むように情報を提示する

### 記憶負荷を減らす原則

**認識 vs 想起：**
- ユーザーに「思い出させる」のではなく「認識させる」
- 例：テキスト入力 vs ドロップダウン（認識のほうが負荷が低い）
- Memory Bridge（メモリブリッジ）の違反を避ける

**情報の可視化：**
- 重要な情報は常に表示する
- 隠れた情報は最小限にする
- 必要な情報は操作時に提示する
- Hidden Navigation（隠れナビゲーション）の違反を避ける

**文脈の提供：**
- 現在の状態を明確に示す
- 操作の結果を予測できるようにする
- エラー時は原因と解決方法を提示する

## 注意の向け方（視覚階層、情報の優先順位）

### 注意の特性

人間の注意は**限られたリソース**である。

**注意を引く要素：**
- コントラスト（色、サイズ、明度）
- 動き（アニメーション）
- 位置（画面の上部、中央）
- 新奇性（予期しない要素）

### 視覚階層の設計

**優先順位の明確化：**
1. 最重要：最も目立つ（大きい、コントラストが高い、上部）
2. 重要：中程度の強調
3. 補助的：控えめな表現

**判断に迷うケース：**
- 複数の重要要素がある場合
- 判断：ユーザーの主要なタスクに焦点を当て、段階的に情報を提示する
- Visual Noise Floor（ビジュアルノイズフロア）の違反に注意する

### 情報の優先順位付け

**優先順位の判断軸：**
1. ユーザーの主要な目標は何か
2. 現在のコンテキストで必要な情報は何か
3. 次に必要な操作は何か

**実践的な原則：**
- 主要なアクションを最も目立つ位置に配置する
- 補助的な情報は折りたたむか、控えめに表示する
- エラーや警告は適切な優先度で表示する（過度な強調は注意散漫を招く）
- アクションボタンはプライマリ1つ + セカンダリ1〜2つに制限する

## 判断に迷いやすいポイント

### 情報量の調整

**判断基準：**
- ユーザーの主要なタスクに必要な情報は表示する
- 補助的な情報は必要に応じて展開可能にする
- 一度に提示する選択肢は4項目を目安にする（Cowanの限界）
- 4を超える場合はグルーピングやカテゴリ分けで対処する

**トレードオフ：**
- 情報の完全性 vs 認知負荷
- 判断：主要タスクに必要な情報を優先し、詳細は段階的に開示する

### 一貫性と最適化のバランス

**判断基準：**
- 基本パターンは一貫させる
- 明確な理由（ユーザー体験の向上、文脈に応じた最適化）がある場合のみ例外を許容する

**判断例：**
- 通常のフォーム：一貫したパターンを使用する
- 特殊な入力（日付範囲選択等）：専用UIも可、ただし理由を明確にする

### 視覚的強調の程度

**判断基準：**
- 最重要要素は明確に強調する
- 過度な強調は注意散漫を招く
- 複数の強調要素がある場合は優先順位を明確にする

**判断例：**
- 主要なCTAボタン：明確に強調する
- 補助的なリンク：控えめに表示する
- エラーメッセージ：適切な強調（過度ではない）

## よくある失敗パターン

- **情報の過剰提示（Wall of Options）**
  - 例：同一画面に選択肢を詰め込み過ぎる
  - 改善：段階的開示と優先順位の整理。4項目以内のチャンクに分割する
  - 参照：Wall of Options 違反パターン

- **画面間の記憶要求（Memory Bridge）**
  - 例：入力に必要な情報が別画面にあり、ユーザーが記憶して戻る必要がある
  - 改善：必要な情報を操作画面に提示する。比較は同一画面で行えるようにする
  - 参照：Memory Bridge 違反パターン

- **視覚的強調の乱用（Visual Noise Floor）**
  - 例：主要ボタンと補助リンクが同じ強度で強調される
  - 改善：強調レベルを分け、Primaryを絞る
  - 参照：Visual Noise Floor 違反パターン

- **一貫性の破綻（Inconsistent Pattern）**
  - 例：同じ操作で異なる結果や表現が混在する
  - 改善：基本パターンを統一し、例外は理由を明示する
  - 参照：Inconsistent Pattern 違反パターン

- **専門用語の乱用（Jargon Barrier）**
  - 例：エラーメッセージに「404」「500」などの技術用語のみが表示される
  - 改善：ユーザーの言葉で状況と解決方法を説明する
  - 参照：Jargon Barrier 違反パターン
