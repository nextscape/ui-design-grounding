# 評価レポート出力

`audit-ui` / `score-ui` / `legibility-ui` が評価結果を Markdown レポートとして残すための共通ルール。評価観点・採点基準・詳細な出力テンプレートは各スキル側に持たせ、このファイルは保存先・メタ情報・スクリーンショットリンクの扱いだけを定義する。

## 保存先

評価レポートは、評価対象プロジェクトの `.design/reports/` 配下に保存する（`.design/` は UI 作業の生成物を集約するディレクトリ。全体構造は `feature-design.md` を参照）。

| 種別 | パス |
|---|---|
| レポート | `.design/reports/YYYY-MM-DD/HHmmss-<skill>.md` |
| スクリーンショット | `.design/reports/YYYY-MM-DD/screenshots/HHmmss-<skill>-NN.png` |

- `YYYY-MM-DD` と `HHmmss` は実行環境のローカル時刻を使う。
- `<skill>` は `audit-ui` / `score-ui` / `legibility-ui` のいずれかを使う。
- 同一秒に複数レポートを出す場合は `HHmmss-<skill>-2.md` のように連番を付けて上書きを避ける。
- スクリーンショットの `NN` は `01` から始め、取得順に連番を付ける。
- このプラグインリポジトリにはサンプルレポートを追加しない。`.design/reports/` は評価対象プロジェクト側の成果物である。

## 共通メタ情報

各レポートの冒頭には、スキル固有のサマリーより前に次のメタ情報を置く。

```markdown
# <スキル名> レポート: <対象>

| 項目 | 内容 |
|---|---|
| スキル | `<skill>` |
| 対象 | <画面・コンポーネント・機能> |
| 実施日時 | <ISO 8601形式のローカル日時> |
| DESIGN.md | あり / なし / 未確認 |
| 観察方法 | Playwright MCP / 未実施（理由） |
| レポート保存先 | `.design/reports/YYYY-MM-DD/HHmmss-<skill>.md` |
```

- DESIGN.md が無い場合は、該当スキルのルールに従って `/init-design` または `/scan-ui` を推奨する。
- MCP が使えない場合は、観察方法に「未実施（Playwright MCP 利用不可）」のように理由を書き、実測・操作が必要な項目を「未検証」にする。

## スクリーンショット一覧

スクリーンショットを取得した場合は、共通メタ情報の直後に一覧を置く。リンクはレポートファイルからの相対パスにする。

```markdown
## スクリーンショット

| # | 内容 | パス |
|---|---|---|
| 1 | <画面・状態・幅など> | [screenshots/HHmmss-<skill>-01.png](screenshots/HHmmss-<skill>-01.png) |
```

取得していない場合は次のように明示する。

```markdown
## スクリーンショット

なし
```

## 本文構成

スクリーンショット一覧の後に、各スキルの `SKILL.md` が定義する出力フォーマットを続ける。共通して次の順序を守る。

1. 冒頭サマリー（総合判定、スコア、P0/P1件数、次にやること）
2. 評価結果の一覧表
3. 重篤度順またはレンズ別の詳細
4. 推奨アクション
5. 未検証・制約

会話内の最終応答では、詳細をすべて再掲せず、冒頭サマリー・最優先アクション・保存先パスを短く示す。

## 未検証・制約

レポート末尾には、必ず「未検証・制約」を置く。

```markdown
## 未検証・制約

- <未検証項目または制約>
```

未検証や制約がない場合も、「なし」と明記する。

## 指摘のフォローアップ（タスク管理への接続）

評価レポートは「出して終わり」にすると、その場で修正されなかった指摘（特に `/design-ui` 級の構造問題）が放置され、後日ユーザーが同じ問題を再発見することになる。レポート保存後、必ず次を行う。

1. P0/P1 の指摘のうち、この実行内（または直後の修正フェーズ）で修正しないものを列挙する。
2. 評価対象プロジェクトにタスク管理（タスクボード・issue・TODO ファイル等）があれば、1 指摘 = 1 エントリで登録する（レポートパスと指摘の識別子を添える）。無ければ、会話の最終応答で「未対応の P0/P1 一覧」を明示し、タスク登録を提案する。
3. 登録した内容（どこへ何件）を、レポートの「推奨アクション」の直後に「未対応指摘の登録先」として追記する。

P2/P3 の登録は任意だが、複数回の評価で同じ指摘が繰り返される場合は登録へ昇格する。
