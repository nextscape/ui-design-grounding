## このドキュメントの役割
モーションデザインの判断基準と実践指針を提供する。デュレーション、イージング、性能最適化、アクセシビリティ対応の判断軸を体系化する。

## モーションデザインとは何か
UIの状態変化やフィードバックをアニメーションで伝え、ユーザーの理解と快適さを向上させること。目的：

- 操作結果の即座のフィードバック
- 状態変化の視覚的な連続性
- ユーザーの注意の適切な誘導
- 空間的な関係性の伝達
- 知覚的パフォーマンスの向上

## デュレーション体系

変化の種類と規模に応じて段階的に設定する。

| カテゴリ | デュレーション | 用途 |
|---------|-------------|------|
| 即座のフィードバック | 100-150ms | hover、active states、ボタン押下 |
| 状態変化 | 200-300ms | トグル、スイッチ、タブ切り替え |
| レイアウト変化 | 300-500ms | アコーディオン、パネルスライド |
| エントランス | 500-800ms | ページ遷移、セクション入場 |

**判断基準：**
- 上記はデフォルト値。コンテキストにより調整可
- 退出は入場の約75%に設定。ユーザーは次のアクションに移りたいため待たせない
- 小さい要素ほど短く、大きい要素ほど長く
- 長すぎると「遅い」、短すぎると変化に気づかない

## イージングカーブ

加速・減速パターンを用途に応じて選択する。

| イージング | 用途 | 理由 |
|-----------|------|------|
| ease-out | 入場（要素が到着） | 速く動き目的地で減速。自然な到着感 |
| ease-in | 退出（要素が去る） | ゆっくり動き始め加速。自然な離脱感 |
| ease-in-out | トグル、状態切り替え | 両端で緩やか、中間で速い。位置の入れ替わりに適する |

**`ease` を使わない。** CSSデフォルトの `ease` は中途半端で意図が不明確になる。

### 推奨する指数関数カーブ

標準イージングより指数関数カーブのほうが自然に動く。

```css
:root {
  --ease-out-quart: cubic-bezier(0.25, 1, 0.5, 1);
  --ease-out-quint: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);
}
```

**判断基準：**
- 入場には `--ease-out-quart` または `--ease-out-quint` を推奨
- より劇的な減速が必要なら `--ease-out-expo`
- バウンス/エラスティックは使わない。実物体はスムーズに減速し跳ね返らない。古臭い印象を与える

## アニメーション性能ルール

### 最重要ルール：transform と opacity のみアニメーションする

`transform` と `opacity` のみをアニメーションする。これが最重要ルール。

**理由：** この2つはコンポジターレイヤーで処理され、レイアウト/ペイント再計算を起こさない。他プロパティ（`width`, `height`, `padding`, `margin` 等）はレイアウト再計算を起こしフレーム落ちの原因になる。

### 禁止されるプロパティのアニメーション

- `width`, `height`
- `padding`, `margin`
- `top`, `left`, `right`, `bottom`（`position: absolute/fixed` 時。代わりに `transform: translate()`）
- `border-width`
- `font-size`

### 高さアニメーションの代替手段

高さ変化（アコーディオン等）には `grid-template-rows` を使う。

```css
.accordion-content {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows 300ms var(--ease-out-quart);
}
.accordion-content[data-open="true"] { grid-template-rows: 1fr; }
.accordion-content > .inner { overflow: hidden; }
```

### will-change の使用制限

- 先行使用は禁止。ブラウザ自身が最適化するため、事前設定はメモリを無駄に消費する
- 測定でボトルネックが確認された場合のみ限定的に使用

### スクロールトリガーアニメーション

- Intersection Observer API で実装する
- `scroll` イベントリスナーは避ける（パフォーマンス悪化）

```javascript
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        entry.target.classList.add('visible');
        observer.unobserve(entry.target);
      }
    });
  },
  { threshold: 0.1 }
);
```

## スタガリング

リスト要素やカード群を順番にアニメーションさせるパターン。

```css
.stagger-item {
  opacity: 0;
  transform: translateY(16px);
  animation: stagger-in 300ms var(--ease-out-quart) forwards;
  animation-delay: calc(var(--i, 0) * 50ms);
}
@keyframes stagger-in {
  to { opacity: 1; transform: translateY(0); }
}
```

HTMLでは各要素に `style="--i: 0"`, `"--i: 1"` … とインデックスを渡す。

**判断基準：**
- アイテム間ディレイは 30-80ms（50ms を推奨）
- 合計スタガー時間は 300-500ms 以内に収める。長すぎると効果が薄れユーザーを待たせる
- アイテム数が多い場合は表示中の要素のみスタガリングし、残りは一括表示

## prefers-reduced-motion 対応

### 必須対応（オプションではない）

`prefers-reduced-motion` への対応は**必須**。

**理由：**
- 40歳以上の成人の約35%がモーションに敏感
- 前庭障害を持つユーザーには過度なアニメーションが身体的不快感を引き起こす
- WCAG 2.1 達成基準 2.3.3（インタラクションによるアニメーション）に関連

### 実装パターン

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.2s !important;
  }
  /* クロスフェードは維持（移動を伴わない opacity 変化） */
  .fade-transition { transition: opacity 0.2s ease; }
}
```

**判断基準：**
- 装飾的アニメーション（エントランス、パララックス、ホバー等）は無効化またはクロスフェードに代替
- 機能的インジケーター（ローディングスピナー、プログレスバー等）は維持。処理中フィードバックは無効化しない
- 完全削除でなく、クロスフェード（`opacity` のみのトランジション）で代替

## 知覚的パフォーマンス

ユーザーが感じる速度は実際の処理速度と異なる。モーションで知覚的パフォーマンスを向上させる。

### 80ms 閾値
- 操作から 80ms 以内のフィードバックは「即座」と感じる
- 超えると「待っている」感覚が生じ始める
- ボタンの `:active` 等、即座のフィードバックはこの閾値内に収める

### 先行開始（Preemptive Start）
アクション前に準備を開始する。例：`mousedown` でアニメーション準備、`click` で実行／`hover` でリソースのプリフェッチ。

### 早期完了（オプティミスティックUI）
処理完了前にUIを成功状態へ更新する。
- 適する：いいね、ブックマーク等の低リスク操作、テキスト保存
- 適さない：決済処理、データ削除、外部サービスへの送信

### 知覚時間の圧縮
- タスク終了に向けて `ease-in` を適用すると待ち時間が短く感じる
- プログレスバーが最後に加速するパターンは、実処理時間と無関係に体感速度を上げる

## 判断に迷いやすいポイント

### アニメーションを付けるべきか

**判断基準：** 状態変化を伝えているか（機能的か）／操作へのフィードバックか／空間的関係性の理解を助けるか

**判断例：**
- タブ切り替えのコンテンツスライド → 付ける（空間的関係性）
- ページ全体のフェードイン → コンテキスト次第（初回訪問は効果的、ページ内遷移は不要な場合あり）
- ボタンのホバーエフェクト → 付ける（フィードバック）
- ロゴの回転 → 付けない（装飾的、目的不明確）

**トレードオフ：** ガイド vs 注意散漫。タスク達成を支援するなら付ける、注意を逸らすなら付けない。

### デュレーションの微調整

**判断基準：** 要素サイズ（大きいほど長く）／移動距離（長いほど長く）／操作頻度（頻繁なほど短く）

**判断例：**
- ドロップダウン開閉（頻繁、小さい）→ 200ms
- モーダル表示（まれ、大きい）→ 300-400ms
- ページ遷移（まれ、全体）→ 500ms

**トレードオフ：** 知覚的パフォーマンス vs 実装複雑性。高頻度操作ほど最適化の投資対効果が高い。

### バウンス/エラスティック vs スムーズな減速

**判断基準：**
- 原則使用しない
- 例外：ゲーム的UIや意図的に遊び心を演出する場合のみ検討
- ビジネスアプリ、情報提供サイトでは使用しない

**トレードオフ：** デライト vs 抑制。プロフェッショナルな印象優先ならスムーズな減速。カジュアル優先でもバウンスは慎重に。

## よくある失敗パターン

- **バウンス/エラスティックイージングの使用** — 改善：`ease-out-quart`/`ease-out-quint` でスムーズに減速
- **レイアウトプロパティのアニメーション** — `width`/`height` のトランジション。改善：`transform: scale()` や `grid-template-rows` で代替
- **目的のないアニメーション** — ロゴ回転、背景パルス。改善：全アニメーションに機能的目的（フィードバック、空間関係、状態変化）を持たせる
- **過剰なアニメーション** — 全要素が独立して動く。改善：注目すべき変化にのみ適用し全体の動きを抑制
- **prefers-reduced-motion 未対応** — 改善：`@media (prefers-reduced-motion: reduce)` でクロスフェードに代替し、機能的インジケーターのみ維持
- **CSSデフォルトの `ease` に依存** — `transition: all 0.3s ease` の使い回し。改善：用途別の指数関数カーブをカスタムプロパティで定義し使い分け
- **`will-change` の乱用** — 改善：使用せずブラウザの最適化に任せ、測定で問題確認時のみ限定使用
- **scroll イベントリスナーによるスクロールアニメーション** — 改善：Intersection Observer API を使用
