## このドキュメントの役割
色の**意味・状態・階層・アクセシビリティ**を一貫して扱うための判断基準を提供する。単独の正解ではなく、文脈・制約・ブランド方針と組み合わせて参照する。

---

## 色設計の目的

- **意味の共有**：色が示す状態・優先度・意図を明確にする
- **一貫性**：画面や機能を跨いで同じ意味を同じ色で表現する
- **可読性**：背景と文字・アイコンのコントラストを崩さない
- **可視性**：重要な情報や操作を埋もれさせない
- **拡張性**：テーマ・ブランド変更に耐える構造を作る
- **知覚的均一性**：人間の目に等しく見える色差を保つ

## モダンCSSカラー関数

### OKLCH（推奨アプローチ）

**知覚的に均一な色空間**で、色の設計・管理に最適。

```css
color: oklch(L C H);
/* L: 明度 (0%〜100%), C: 彩度 (0〜0.4程度), H: 色相 (0〜360) */
```

**推奨理由：**
- 明度を変えても色相がずれない（HSLは明度変更で色相シフトが起きる）
- 彩度調整が直感的でパレット生成が容易
- ダークモードは明度チャンネルだけ操作すればよい

**明度と彩度の関係（重要）：** 白に近い（高明度）ほど、黒に近い（低明度）ほど彩度を下げる。最も鮮やかに見えるのは中間明度帯（L: 55%〜75%程度）。これを無視すると不自然に浮いた色やくすんだ色が生まれる。

### color-mix()

2色を指定比率で混合する。

```css
color: color-mix(in oklch, var(--color-primary) 70%, white);
```

**活用場面：** ホバー・アクティブ状態のバリエーション生成、グラデーション生成。OKLCH と組み合わせると知覚的に均一な混合になる。

### light-dark()

ライト/ダークの値を一箇所で定義する。

```css
:root { color-scheme: light dark; }
color: light-dark(oklch(25% 0 0), oklch(90% 0 0));
```

**活用場面：** セマンティックトークンのテーマ切り替え、`prefers-color-scheme` の簡略化。

## 色の構造（レイヤーと役割）

### 1. 基本レイヤー（Surface / Text / Border）

- **Surface**：背景・面を表す色
- **Text**：文字情報の可読性を担保する色
- **Border**：区切り・境界・構造を伝える色

**判断基準：** Surface と Text は必ず十分なコントラストを確保。Border は区切りに必要な最小限の強さに留める。

**ティンテッドニュートラルの原則：** ピュアグレー（彩度ゼロ）はUIを無機質に見せる。Surface レイヤーの全ニュートラルに、ブランドカラーの色相を彩度 ~0.01 で加える。

```css
/* ピュアグレー（避ける） */
--color-surface: oklch(98% 0 0);
/* ティンテッドニュートラル（推奨） */
--color-surface: oklch(98% 0.01 250);  /* ブランドの色相250を微量追加 */
```

**効果：** 視覚的な温かみと統一感、ブランドとの自然な調和。彩度 0.01〜0.015 程度が適切（超えると色付きが目立つ）。全ニュートラルに同じ色相を使い一貫性を保つ。

### 2. 意味レイヤー（Semantic / State）

- **Primary（M3）**：主要操作、注意を引く要素（旧 Action）
- **State**：成功・注意・警告・エラーなど状態の表現（M3 コアは `error`、success/warning/info は最小拡張）
- **Feedback**：hover / active / disabled / focus など動作の表現（状態サフィックスは最小拡張）

**判断基準：**
- 状態色は意味の一貫性を優先し、装飾に流用しない
- hover / active は `color-mix()` で明度差を作ると効率的かつ一貫性が保てる
- セマンティックトークンとして定義し、ダークモードはこのレイヤーのみ再定義する

```css
/* color-mix() によるステートバリエーション（hover/active は M3 への最小拡張） */
--color-primary: oklch(55% 0.2 250);
--color-primary-hover: color-mix(in oklch, var(--color-primary) 85%, white);
--color-primary-active: color-mix(in oklch, var(--color-primary) 85%, black);
```

### 3. 階層レイヤー（Hierarchy / Emphasis）

- **Primary**：最も重要な情報・操作
- **Secondary**：補助的な情報・操作
- **Muted**：背景的な情報・補助表示

**判断基準：** 強調は色だけに依存せずサイズ・配置も併用する。Primary が多すぎると優先度が崩れる。

**60-30-10 ルール：** 画面全体の色配分バランスの指針。
- **60%：ニュートラルカラー**（Surface、背景、余白）
- **30%：セカンダリカラー**（カード、セクション背景、補助テキスト）
- **10%：アクセントカラー**（CTA、アクティブ状態、重要な強調）

この比率を大きく逸脱すると視覚的ノイズや階層崩壊が起きる。特にアクセントが10%を超えると強調の意味が薄れる。

## 色の使い分け指針

### 意味がある色（Semantic）を優先する
- 色は「値」ではなく「意味」で管理する（トークン化）
- 例（正規の役割語彙 = Material 3 系、`design-tokens.md` が所有）：`on-surface` / `primary` / `error`

### 目立たせたいから色を変える、を避ける
- 色は意味付けの道具であり、装飾目的で乱用しない
- 強調が必要ならまず「情報階層の再設計」を検討する

### 状態色の整合性
- 同じ状態は同じ色で表現する（成功=緑、警告=黄、エラー=赤 など）。ブランド方針があればそれに従う
- 「警告」と「エラー」を混同しない（強度を分ける）

### アルファ透明度の扱い
アルファ透明度（rgba の a や oklch の / alpha）の多用は**パレットが不完全であるサイン**。

- **適切：** オーバーレイ（モーダル背景）、フォーカスリング、スケルトンスクリーン
- **代替すべき：** ホバー状態の色差（→専用トークン）、ボーダー色（→`outline` を Surface との組み合わせで明示定義）、テキストの薄い表現（→`on-surface-variant` トークン）

透明度を3箇所以上使う場合はパレット見直しを検討する。

## ダークモード設計

ダークモードは**ライトモードの反転ではなく**、独立した設計思想に基づくもう一つのカラーシステムである。

### 基本原則

**1. 純粋な黒を使わない**
`#000000`（oklch 0%）は目に負担がかかりコントラストが過剰。背景色は oklch 12%〜18% の範囲を基準にする。

```css
/* 避ける */ --color-surface: oklch(0% 0 0);     /* 純黒 */
/* 推奨 */   --color-surface: oklch(15% 0.01 250); /* ティンテッドダーク */
```

**2. 深度の表現にはサーフェスの明度を使う**
ライトモードは影（box-shadow）で深度を表すが、ダークモードは影が見えにくいため**面の明度を上げて深度を表現する**。

```css
--color-surface:                oklch(15% 0.01 250);  /* 最背面 */
--color-surface-container:      oklch(20% 0.01 250);  /* 浮いた面 */
--color-surface-container-high: oklch(25% 0.01 250);  /* モーダル・ドロワー */
```

**3. アクセントカラーの彩度を少し落とす**
暗い背景上では高彩度の色がギラつく。ダークモードのアクセントは彩度を 10〜20% 落とす。

```css
/* ライトモード */    --color-primary: oklch(55% 0.22 250);
/* ダークモード（彩度↓）*/ --color-primary: oklch(70% 0.18 250);
```

**4. テキストのウェイトを少し軽くする**
暗背景＋明テキストは同じウェイトでも太く見える（ハレーション効果）。`font-weight` を1段階下げることを検討する。

**5. セマンティックトークンレイヤーのみ再定義する**
プリミティブトークンは変更せず、セマンティックトークンのマッピング切り替えでテーマを実現する。

```css
/* プリミティブ（テーマで変更しない） */
--blue-500: oklch(55% 0.22 250);
--gray-100: oklch(95% 0.01 250);
--gray-900: oklch(15% 0.01 250);
/* セマンティック（テーマで切り替える） */
:root {
  color-scheme: light dark;
  --color-on-surface: light-dark(var(--gray-900), var(--gray-100));
  --color-surface: light-dark(var(--gray-100), var(--gray-900));
}
```

### ダークモード設計のチェックリスト
- [ ] 背景色は oklch 12%〜18% の範囲である（純黒ではない）
- [ ] ニュートラルにティンテッドカラーが使われている
- [ ] 深度は面の明度差で表現している（影だけに頼っていない）
- [ ] アクセントカラーの彩度がライトモードより低い
- [ ] テキストのコントラスト比は 4.5:1 以上だが 15:1 を大きく超えない
- [ ] セマンティックトークンの再定義で対応している（プリミティブは変更していない）

## トークン設計との関係

### トークンの階層構造

**1. プリミティブトークン（値の集合）** — 色の実値。テーマで変更しない。

```css
--blue-500: oklch(55% 0.22 250);
--blue-600: oklch(48% 0.22 250);
--red-500: oklch(55% 0.22 25);
--gray-100: oklch(95% 0.01 250);  /* ティンテッドニュートラル */
--gray-900: oklch(15% 0.01 250);
```

**2. セマンティックトークン（意味・役割）** — UIの役割を表す。テーマ切り替えはこのレイヤーで行う。

```css
--color-on-surface: var(--gray-900);
--color-surface: var(--gray-100);
--color-primary: var(--blue-500);
--color-error: var(--red-500);
```

### 推奨トークンのカテゴリ（M3 コア + 最小拡張）

正規の役割語彙は `design-tokens.md`（Material 3 系）が所有する。M3 で表現できない階調のみ、最小拡張（◇印）として補う。

- **テキスト**：`on-surface`（primary）/ `on-surface-variant`（secondary）/ ◇`on-surface-muted`（muted）/ `inverse-on-surface`（inverse）
- **サーフェス**：`surface` / `surface-container`（elevated）/ `surface-container-high`（overlay）
- **ボーダー**：`outline`（default）/ `outline-variant`（subtle）/ ◇`outline-strong`（strong）
- **アクション**：`primary` / `on-primary` / `secondary`（ghost はボタン変種＝コンポーネント側の関心）
- **状態**：`error` / `on-error`（M3 コア）/ ◇`success` / ◇`warning` / ◇`info`（最小拡張）
- **フォーカス**：◇`focus`（最小拡張。多くは `primary` を流用可）

### ガイドライン
- UI上では **semantic token** を優先使用する
- 直接値（#xxx や oklch直書き）の使用は例外に限定する
- ダークモード対応はセマンティックトークンの再定義で実現する
- 役割語彙（Material 3 系）の正規定義・命名・段階導入は `reference/design-tokens.md` を参照する

## アクセシビリティ観点の色設計

色設計で押さえる要点のみ記す。**コントラスト比の基準値・フォーカスリングの視認性・色覚多様性の判定は `accessibility.md` が所有する**（テキスト4.5:1 / UI・大文字3:1 等）。

- **コントラスト**: ライト/ダーク双方で基準比を満たすか検証（暗背景＋明テキストを特に確認）
- **色覚多様性**: 色だけに依存せず形状・アイコン・テキストで補助。色相差が小さい組み合わせ（赤×緑等）は要注意
- **フォーカス**: リングは背景と十分なコントラストを取る（実装は `interaction.md`）

## 危険な色の組み合わせ

以下はコントラスト不足や可読性の問題を引き起こす。設計・レビュー時に必ず確認する。

### 高リスクの組み合わせ

| 組み合わせ | 問題 | 対策 |
|---|---|---|
| 薄いグレーテキスト on 白背景 | コントラスト不足で読めない | `on-surface-variant` でも 4.5:1 を確保する |
| グレーテキスト on 色付き背景 | 背景色と溶け込む | 色付き背景には白/黒テキストを使う |
| 赤テキスト on 緑背景 | 色覚多様性で判別不可 | 色以外の識別手段を追加する |
| 青テキスト on 赤背景 | 色収差で文字がにじむ | 高彩度同士の組み合わせを避ける |
| 黄色テキスト on 白背景 | コントラスト不足 | 黄色は背景用に限定する |

### 検出方法
- デザインファイルのコントラスト比を機械的にチェックする
- グレースケール変換で色だけに依存した表現がないか確認する
- 色覚シミュレーションツール（P型・D型）で検証する

## よくある失敗パターン

### 純黒（#000）/ 純白（#fff）の使用
- **問題**：コントラストが過剰で目が疲れる。特にダークモードの `#000` 背景は非常に不自然
- **改善**：ティンテッドニュートラルを使う。最暗色は oklch 12〜18%、最明色は oklch 95〜98% を基準にする

### AI的パレット（サイバー配色）・グラデーションテキスト
- 色起点の改善のみ：ブランドカラーを起点にパレット構築し、高彩度アクセントは10%以下の面積に限定。テキストは単色で可読性優先（グラデーションは背景・アイコンに限定）
- **AI slop の全体像・判定（3項目該当で疑い）・意図的デザインとの対比表は `anti-patterns.md` が所有する**

### グレーテキスト on 色付き背景
- **問題**：背景色に溶け込んで読めなくなる
- **改善**：十分なコントラストがある白か黒のテキストを使う

### 状態色の意味が一貫しない
- **問題**：成功にも警告にも同じ色を使う
- **改善**：状態ごとの色をセマンティックトークンとして明確に分ける

### 強調色の乱用
- **問題**：複数の重要要素が同じ強調色で、すべてが「主役」になる
- **改善**：60-30-10 ルールに基づきアクセントカラーの面積を制限する

### 背景とテキストのコントラスト不足
- **問題**：薄いグレー文字が背景と同化している
- **改善**：OKLCH の明度値でコントラスト比を計測・調整する

### アルファ透明度の多用
- **問題**：ホバー状態やボーダーなど、あらゆる場所で透明度に頼る
- **改善**：パレットを見直し、必要な色を明示的にトークンとして定義する

## このreferenceの使い方

以下のコマンドスキルから参照される:
- `audit-ui` — 技術品質監査のカラーコントラスト・アクセシビリティ評価時に参照
- `init-design` — デザインガイドライン策定時のカラーシステム設計に参照
- `design-ui` — UI設計時のカラーパレット・セマンティックカラー設計に参照
- `implement-ui` — UI実装時のCSS カラー関数・トークン実装に参照
- `extract-ui` — トークン抽出・リファクタリング時のカラートークン設計に参照
- `boost-ui` — 視覚的インパクト強化時のカラー階層設計に参照
- `calm-ui` — 視覚的ノイズ軽減時のカラーバランス調整に参照

**関連リファレンス:**
- `design-tokens.md` — トークンの階層構造・命名・段階導入の詳細
- `accessibility.md` — コントラスト比・色覚多様性の基準
- `anti-patterns.md` — AI典型パレット・グラデーションテキスト等の色関連アンチパターン
