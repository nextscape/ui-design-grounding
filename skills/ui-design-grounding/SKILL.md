# ui-design-grounding

## 目的・スタンス

- UI/UXの判断・提案・改善・修整を、**理由と前提を明示しながら安全に進める**。
- 「UIを良くする」断定ではなく、**判断軸を共有し、人間と合意可能な形で実行に落とす**。
- 最終的な採否・意思決定は、常に人間が行う。

**守るべきスタンス**

- 判断に使う前提・制約を明示する
- 適用している（または欠けている）原則・ガイドラインを整理する
- 選択肢は理由付きで複数提示する
- 主観的好みのみの断定は避ける

具体的な実装プランが既に存在する場合でも、本Skill配下の reference を**ガイドラインとして参照**したうえで実装せよ。

## このSkillの役割

本スキルは **ナレッジベース** である。

- 15個のリファレンス（`reference/`）にUI/UX設計の判断基準・原則・パターンを集約
- 17個の独立コマンドスキルが MANDATORY PREPARATION として本スキルのリファレンスを参照する
- 本スキル自体はユーザーが直接呼び出すのではなく、コマンドスキル経由で利用される

## 設計判断と前提の扱い

UI設計・実装の判断は、明示／暗黙いずれかのルールや前提に依存している。作業前に次を判定せよ。

- 判断軸やガイドラインが明示されているか
- 暗黙的なルールとして存在しているか
- ほぼ存在しない／不明確か

前提が不明確な場合は、**`/init-design` で DESIGN.md を生成**すること。

**最低限確認すべき情報**

- 対象の画面・機能・ユーザーフロー
- 想定ユーザー層・利用状況・主要タスク
- ビジネス目的・KPI・制約（法務 / 運用 / 技術）
- 既存のデザインシステム / コンポーネント / トークンの有無
- 実装スタック（例: React / HTML / CSS、デザイントークン運用など）

---

## 出力ポリシー

- 主観的な感想ではなく、**理由と根拠を伴う説明**を行う
- 「良い／悪い」の断定ではなく、**選択肢とトレードオフ**を提示する
- 提案・修整は、前提や仮定を明示したうえで行う
- 改善案・設計案は可能な範囲で複数提示する
- 不足情報がある場合は、仮定として明示したうえで判断する
- 特別な指示がなければ、既存コンポーネント・CSS・デザイントークンの再利用を優先する
- 判断や最終選択は、必ず人間に委ねる

## 注意事項・制約

- 文脈や制約を無視した機械的な適用は行わない
- 判断の前提やガイドラインは、必要に応じて更新されうるものとして扱う
- 入力情報が極端に不足している場合、分析は仮定ベースとなり、精度に限界がある
- プロジェクト固有のKPIやビジネス制約が共有されない場合、UX判断は限定的になる
- 感情的・美的評価のみを求められた場合、本Skillの出力は期待とズレる可能性がある
