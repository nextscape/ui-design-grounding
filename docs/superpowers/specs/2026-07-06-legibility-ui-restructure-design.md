# legibility-ui 全面再構成 設計仕様

- **日付**: 2026-07-06
- **対象**: `legibility-ui` スキルの6レンズ（①〜⑥）を、実施範囲・意味的な近さに基づいて再構成し、番号を振り直す。あわせて各レンズに典型例を12項目追加する
- **ステータス**: 設計合意済み（実装計画はこの後 writing-plans で作成）

## 1. 背景・目的

`legibility-ui`（`2026-07-05-legibility-ui-integration-design.md` で統合、`2026-07-06-legibility-ui-lens6-design.md` でレンズ⑥を追加）の網羅性・構成をさらに改善する。

現状の6レンズ体制には以下の課題があった:

1. 本文の並び順（①②③④⑤⑥、レンズ定義順）と出力フォーマットの並び順（①②③④⑥⑤、実施頻度順）が不一致
2. 6レンズがフラットに並んでおり、意味的な近さ（例: ①見た目と機能の不一致、⑥現在地の不透明さ は共に「見た目から意味を読み取れるか」という近い性質）が整理されていない
3. 番号（①〜⑥）だけでは、そのレンズが単一画面で完結するのか、複数画面比較が必要なのかが分からない

これらを一挙に解消するため、番号体系を振り直し、意味的なグルーピングを導入する。

## 2. 新しい番号体系とグルーピング

**大分類**（実施範囲を最上位の分類軸にする）:

- **A. 単一画面完結レンズ**（対象画面数によらず常に実施）: 新①〜⑤
- **B. 画面横断レンズ**（対象2画面以上のときのみ実施）: 新⑥

**Aグループ内のサブグルーピング**（意味的な近さで整理）:

- **A-1 見た目の意味**（見た目・状態表示から機能や位置づけを正しく読み取れるか）
- **A-2 存在・機能の理解**（機能の存在理由・影響範囲を理解できるか）
- **A-3 情報の整理**（同じ情報・機能が整理されているか）

**新旧番号マッピング**:

| 新番号 | レンズ名 | 旧番号 | 大分類 |
|---|---|---|---|
| ① | 見た目と機能の不一致（Affordance Mismatch） | 旧① | A-1 見た目の意味 |
| ② | 現在地の不透明さ（Orientation Loss） | 旧⑥ | A-1 見た目の意味 |
| ③ | 目的の不透明さ（Purpose Opacity） | 旧② | A-2 存在・機能の理解 |
| ④ | スコープ不整合（Scope Mismatch） | 旧③ | A-2 存在・機能の理解 |
| ⑤ | 重複・冗長表示（Redundancy） | 旧④ | A-3 情報の整理 |
| ⑥ | 画面間一貫性（Cross-Screen Consistency） | 旧⑤ | B 画面横断 |

新番号体系のメリット: 「①〜⑤は常に実施、⑥のみ2画面以上」という規則が番号だけで判別できるようになり、SKILL.md側の分岐説明もシンプルになる。

見出し階層は既存の2階層（`## 6つのレンズ` → `### ① 〜 ⑥`）を維持し、大分類・サブグループは見出しレベルを増やさず、次の2箇所で軽量に表現する:
- `## 6つのレンズ` の直下に、大分類・サブグループの構成を説明する短い前文を追加
- 各レンズ見出しに `[A-1 見た目の意味]` のようなタグを付記

## 3. 各レンズへの典型例追加（12項目）

既存の典型例と重複せず、実務でよく見られるパターンを各レンズに2件ずつ追加する。

**① 見た目と機能の不一致**
- 色の意味の誤用（危険な操作なのに警告色でない、逆に単なる強調が警告色に見えて危険な操作だと誤解させる）
- 慣用的アイコンの意味との乖離（ゴミ箱=削除、フロッピー=保存等、広く定着した記号がその画面では異なる意味で使われている）

**② 現在地の不透明さ**
- スクロール中に見出し・現在地の手がかりが画面外に消え、長いページで今どのセクションを読んでいるか見失う
- タブ/アコーディオンで、現在選択中・展開中の項目を示す視覚的な手がかりが不明瞭

**③ 目的の不透明さ**
- アイコンのみでラベルもツールチップもないボタン（何のボタンか名前すら分からない）
- バッジ・カウンター数字の意味が不明（未読数／合計数／新着数のどれを指すか区別がつかない）

**④ スコープ不整合**
- 「すべて」に見える操作（全選択・全削除等）が、実は現在のフィルタ・表示範囲にしか効かない（または逆に、限定的に見える操作が全体に効く）
- ある変更が即座に反映されるのか、保存ボタンを押すまで確定しないのかが、操作前の見た目から分からない

**⑤ 重複・冗長表示**
- 同じ操作（削除・編集等）が画面内の複数の場所から提供されており、経路によって挙動が微妙に異なる
- 同一のデータが異なる形式・粒度で並記され（例: 「更新日: 2024-01-01」と「3日前に更新」）、数値がズレて見えることがある

**⑥ 画面間一貫性**
- 同じ用語が画面によって異なる対象を指す（例:「メンバー」が、あるページではプロジェクトメンバー、別ページでは組織メンバーを指す）
- エラー・空状態の表現パターンが画面ごとにバラバラ（あるページはイラスト付きの丁寧な空状態、別ページはテキストのみ）

## 5. スコープ外（YAGNI）

- レンズの統合・削減（6レンズを5つ以下にまとめる等）は検討しない。今回は再構成と典型例追加に留める
- 見出しレベルを増やす完全な階層化（`## 大分類` → `### サブグループ` → `#### レンズ`）は採用しない（3章で決定済み、既存の2階層構造を維持する）
- SKILL.md以外の周辺ドキュメント（README.md、ui-help/SKILL.md、CLAUDE.md）のレンズ数・観点列挙は、今回の番号振り直しによって内容が変わるわけではない（レンズの「数」は6のまま、名称も維持）ため、変更不要
