# legibility-ui レンズ⑥追加 設計仕様

- **日付**: 2026-07-06
- **対象**: `legibility-ui` スキルに新レンズ「⑥ 現在地の不透明さ（Orientation Loss）」を追加し、5レンズ体制から6レンズ体制へ拡張する
- **ステータス**: 設計合意済み（実装計画はこの後 writing-plans で作成）

## 1. 背景・目的

`legibility-ui`（`docs/superpowers/specs/2026-07-05-legibility-ui-integration-design.md` で `ui-design-grounding` へ統合済み）の網羅性を高めるため、既存5レンズがカバーしていない観点を洗い出した。

既存5レンズは共通して「**今見えているものの意味**」（これは何か・なぜここにあるか・何に効くか・重複していないか・画面間で統一されているか）を扱う。一方、「**画面全体における自分の位置づけ（今どこにいるか）**」という空間的・階層的な現在地の把握可能性は、いずれのレンズにも該当しないことが判明した。

## 2. 既存レンズとの重複整理

検討の過程で、既存 ①見た目と機能の不一致（Affordance Mismatch）の典型例に、パンくずや現在地表示への言及が既に存在することが分かった（`reference/legibility.md` 17行目: 「階層・重要度が異なる要素（パンくずの中の各セグメント、ページ見出しとその子要素、現在地とその親カテゴリ等）が同じ文字サイズ・太さ・色で表示され、どちらがより上位／現在地かの手がかりが弱い」）。

これを踏まえ、①と新レンズ⑥の役割を以下のように分担し、重複を避ける。

| | 対象とする状態 | 判定内容 |
|---|---|---|
| ①見た目と機能の不一致（既存、変更なし） | 現在地表示の**要素は存在する**前提 | 要素間の視覚的重み付け（サイズ・太さ・色）が階層の差を正しく表現できているか |
| ⑥現在地の不透明さ（新規） | 現在地表示の**要素の有無・内容**そのもの | 要素が存在するか、存在する場合その内容が実際のコンテンツ・階層と一致しているか |

②目的の不透明さ・③スコープ不整合・④重複冗長表示・⑤画面間一貫性とは、扱う軸が異なり重複しないことを確認済み。

## 3. 新レンズ⑥の定義

### ⑥ 現在地の不透明さ（Orientation Loss）

**問い**: 今、画面のどこ（どの階層・どのセクション）にいるかを、パンくず・見出し・ナビゲーションの状態表示などの手がかりから初見で答えられるか？

**チェック方法**: 画面を開いた瞬間に「これは全体構造のどこに位置する画面か」を自問する。答えられない場合、パンくず・ページ見出し・サイドナビ/タブのアクティブハイライトの**有無**を確認する（視覚的な強弱の判定は①に委ねる）。存在する場合は、その内容が実際のコンテンツ・階層と一致しているかを確認する。

**典型例**:
- 複数階層があるのに、パンくず・現在地表示が画面のどこにも存在しない
- ページ見出しが実際のコンテンツと一致しない、または見出し自体が無い
- サイドバー/タブのナビゲーションで、選択中の項目を示すアクティブ状態の表現（ハイライト・下線等）が一切ない
- 深い階層（3階層以上）なのに、パンくずが直近1階層しか表示しない、または全て省略記号になっている

**判断が割れやすいケース**: 階層が実質1段しかないシンプルな画面構成（トップページのみ等）では、現在地表示自体が不要な場合がある。複数階層が実在するのにその手がかりが一切欠けている場合のみ指摘する。①とは異なり、「表示要素はあるが階層の視覚的重みが弱い」場合はこちらではなく①で扱う。

**実施範囲**: ⑤（画面間一貫性）とは異なり、複数画面の比較は不要。単一画面内で完結する判定のため、対象画面数によらず常に実施する（①〜④と同じ扱い）。

## 5. スコープ外（YAGNI）

ブレインストーミング時に候補として挙がったが今回のスコープに含めない観点（将来の拡張候補として記録）:
- 操作結果の可視性（何をしたら画面がどう変わったか、成功/失敗/処理中のフィードバック）
- 因果関係の可視性（ある操作が別の場所にどう影響したかの関連性）
- 可逆性・危険度の予測可能性（操作が取り消せるか、永続的か、危険かが見た目から分かるか）
